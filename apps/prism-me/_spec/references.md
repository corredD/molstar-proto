# prism-me references: feature → citation dictionary

For the prism-me paper. Each feature of [features.md](features.md) is mapped to the papers it builds on, the tools that
already do it, and an honest call on novelty. Citation keys (`[Sehnal2021]`) are defined in
[references.bib](references.bib). Every entry there was checked on 2026-11-05 against a primary source (Crossref or
DataCite by DOI, PubMed through Europe PMC, arXiv, or the publisher's own page), and its `note` field says which. What
could not be verified is not in the .bib. It is listed under "Unverified (to check)", before the claims.

**How to read the "Novel?" column.** prism-me sits on three layers it did not write: the Mol\* library and graphics
engine [Sehnal2021, Rose2026], the Prism viewer (unpublished), and the Mesoscale Explorer, which it ports [Rose2024]. A
row is **no** when the capability comes from one of those layers or is standard practice. It is **partly** when prism-me
adds something specific to a known technique: a new key, a new data type, the web, or undo. It is **yes** only when no
prior art was found in this search. "No prior art found" means none within ~70 verified sources and targeted searches
(Crossref, Europe PMC, arXiv), not an exhaustive review. Statuses (Done, Partial, Deferred) are features.md's, as of
2026-11-04.

Several rendering techniques the user sees in prism-me (GPU instancing, LOD, frustum and occlusion culling, screen-space
illumination) are claimed by the Mol\* graphics-engine paper [Rose2026]. **Cite them as Mol\*'s, not prism-me's.** The
same holds for the particle model: `ParticleList` and its readers (cellPACK/PetWorld mmCIF, Simularium, STAR, TBL, EM,
NDJSON) are on Mol\* v6 master (`packages/model/src/model/particles/`, `packages/model/src/formats/particles/`;
Alexander Rose, unpublished). prism-me's library changes are the targets by reference, the targets by attribute and the
per-entity Layers (README, "Library changes the app needed").

## Claims for the paper (candidates)

Ranked by how well they hold against the prior art above, after the full-text and abstract checks (ArtiaX full text;
Chameleon, Cuttlefish, Visibility Equalizer, VOICE, ChatVis, ParaView-MCP and copick abstracts). Each claim names the
rows it rests on (section.row, or X1–X4).

1. **Particles decorated by live reference to any scene object.** A particle class (a cryo-ET class or a mesoscale
   ingredient) is drawn as a reference to any object in the scene: a full atomic structure in any Mol\* representation,
   a segmentation mesh or a density map. It is swapped without re-parsing and updated in place when that object changes.
   _Rests on:_ §3 rows 1–4; X1. _Differs from:_ ArtiaX, which draws markers, arrows or isosurfaces of an associated map
   in ChimeraX [Ermel2022]. _Risk:_ small if the paper says what ArtiaX does.
2. **Integrative mesoscale models and cryo-ET picks in one browser scene.** cellPACK, PetWorld and Simularium models and
   RELION, Dynamo, Artiatomi and CryoET Data Portal picks open side by side and share one set of tools: tree, looks,
   cuts, decorations, measurements. _Rests on:_ X1; §1 rows 2–3; §2; §3. _Credit:_ the shared particle model is upstream
   Mol\* v6 (Rose, unpublished; see Unverified). The claim is the application, not the data model. _Differs from:_
   [Rose2024] (mesoscale only), [Ermel2022, Ermel2026] (cryo-ET only, desktop or napari), [Chareshneu2023] (volumes and
   segmentations, no mesoscale models).
3. **Every change is one undoable operation, including the AI assistant's.** The GUI, the command palette and the LLM
   agent call one operation layer, so an agent's edit can be inspected and undone like a user's. _Rests on:_ X2; §4 row
   "Commands for the agent"; the live-drag rows of §2 and §3. _Differs from:_ [Jia2025, Peterka2025, Liu2025,
   Ermel2026], whose abstracts report no undoable agent steps. _Risk:_ check ParaView's undo behaviour under
   ParaView-MCP; fix or disclose the exceptions in architecture.md §5.
4. **CryoET Data Portal runs opened in a molecular viewer.** One undoable operation opens a run: an OME-Zarr tomogram
   (level switchable in place), its tilt series placed in the tomogram's frame with per-image tilt angles, its
   annotations as surfaces, and its picks decorated with atomic models, with DOIs and GO terms kept. _Rests on:_ §3
   portal rows and the OME-Zarr row. _Differs from:_ [Ermel2024] (the portal), [Ermel2026] (copick: napari and
   ChimeraX), [Mena2026] (CoCryoViS: volumes and segmentation, no atomic decoration). _Risk:_ the portal's own viewer is
   unverified (see above).
5. **cellVIEW's per-type cutaways in a web viewer, for any data type.** Per-entity clip mapping with graded band and
   fuzziness, per-type visibility, whole-instance cuts and ghosts, as saved, undoable operations on mesoscale models,
   particle lists and volumes alike. _Rests on:_ §2 row "Clip per entity…"; §4 rows on ghosts, What it cuts, graded
   ways, Shown %, Clip whole. _Differs from:_ [LeMuzic2015, LeMuzic2016] (Unity, desktop; cut state lost on edit,
   cellview.md §6). _Risk:_ mostly a port; present it as "brings to the web and generalises", not as new technique.
6. **Zoom-adaptive coloring keyed to on-screen atom size.** Chameleon-style level blending [Waldin2016] keyed to
   projected atom size and blended in Oklab [Ottosson2020]. _Rests on:_ §2 row "Colors that follow the zoom". _Weak:_
   Chameleon and Cuttlefish already adapt to the current scale [Waldin2016, Waldin2019], and Cuttlefish also
   redistributes color across the view, which prism-me does not. Claim only with a figure across scales (HIV and
   Mycoplasma [Johnson2014, Maritan2022]) and frame it as an implementation choice.
7. **Cross-modal measurement.** Distances, angles and dihedrals between any mix of atoms, particle instances, voxels and
   mesh triangles in one scene. _Rests on:_ §4 measurement rows. _Weakest:_ reviewers may see it as incremental over
   ChimeraX [Pettersen2021].

Do not claim the particle data model, GPU culling, LOD, instancing, OIT, SSAO, shadows, outlines or DVR. These are
upstream Mol\* [Rose2026] or earlier work; cite them as the substrate. A supporting number from features.md (one
observation, not a benchmark): undo on CellPack MG (2.1 M particles) takes about 0.3 s. Measure it properly before using
it.
