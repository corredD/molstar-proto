## Learned

- **`focus` and `highlight` asked every time**: `mvs-tree` declared them `history: false, undoable: false`, and the
  policy asks for every `undoable: false` call (agent.md §4), so "frame the docked granule" would have waited for a yes
  at each frame. prism.md §4.5 and §5.3 call them view changes (`focus.set` is `history: false` only). The flag was
  dropped from both (operation and stub) with a test first. Showing a view, saving and closing still ask.
- **The document is not in the scene's outline**: the agent's state reads the scene tree's nodes only, and a document's
  rows are the explorer's UI, so the model would never have seen the document. `agentState` is the smallest hook that
  puts it in (a library-side change in `prism/viewer`, its own commit); the alternative, the model calling
  `get_mesoviewspec` each turn, is still there for more than 24 lines.
- **The stub imports no code** (a test of `mvs-open`): importing `mesoQLSkill` from the format into it failed that test;
  hence the generated data module.
- **Differences from prism.md §8**: `focus_meso` has `select` only (§4.5 says `framing?`, the operation has none);
  `get`'s `document` detail prints the whole S-expression, not at most the state lines (a document with many populations
  is long); `open`'s and `show_meso_view`'s messages still carry the title and the view's label unquoted (the
  operations' own words); tours (`mesoviewspec.tour.play`) have no tool.
- `meso-molstar` gets `@molstar/ai` as a dev dependency (the scripted model), and its lockfile entry.
- Windows: Biome's `--write` over a directory rewrote every file's line endings (the tree is CRLF, the index LF); the
  untouched ones were restored with `git checkout --`. Biome on the files changed, one by one, is clean.

- **M1, different from the finding**: an edit's compile loads the resources of the document before it
  (`MesoDocumentModel.load` reads `this.session?.doc ?? this.doc`, and `MesoSession` sets `doc = next` only after
  `compile`), so the uri an edit writes is fetched by the **next** model edit (or Undo/Redo), not by the edit itself;
  the edit that writes it draws the old resource and says it succeeded. The approval sits on the writing edit, since the
  one that fetches names no address. The stale load is lane 8's file: under Open for Ludo.
- **S7, more than the finding**: the second agent of the open test never disclosed the skill, so its call failed as not
  loaded and the test passed without running the open. It discloses now; the fetch is stubbed and asserted.
- **S3**: a line cap of 240 cut the exosome's own line (13 populations with counts, ~600 characters) before `p.lipids`
  and `p.catalase`; the cap is 800 a line, 4000 in all, and the agent test checks the line is whole.
- **M3**: an issue's message is now `quoted()`, so at most 80 characters (the person's warnings too).
- **(a)**: a tour's views are a new operation, `mesoviewspec.tour.view` (`undoable: false`), so a tour leaves no step
  per view and is still asked once. Showing the view shown again (its camera only) is `unchanged`: no step. The evals'
  show-a-view routes now pass every check, nothing asked.
- **(b)**: the run reads the document, then refuses the agent's open while a resource is on a host that is neither the
  document's nor a known service and the call does not name it in `resources`; the call that names them has them in its
  `addresses`, so the person is asked (or a domain rule allows them). A new field, `resources`, on `open` and its tool.
- No document-model.ts change (M1 reads the model's public `url`).
