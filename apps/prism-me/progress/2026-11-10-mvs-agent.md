## Learned

- **`focus` and `highlight` asked every time**: `mvs-tree` declared them `history: false, undoable: false`, and the
  policy asks for every `undoable: false` call (agent.md §4), so "frame the docked granule" would have waited for a yes
  at each frame. prism.md §4.5 and §5.3 call them view changes (`focus.set` is `history: false` only). The flag was
  dropped from both (operation and stub) with a test first. Showing a view, saving and closing still ask.
- **The document is not in the scene's outline**: the agent's state reads the scene tree's nodes only, and a document's
  rows are the explorer's UI, so the model would never have seen the document. `agentState` is the smallest hook that
  puts it in (a library-side change in `prism/viewer`, its own commit); the alternative, the model calling
  `get_mesoviewspec` each turn, is still there for more than 24 lines.
- **The stub imports no code** (a test of `mvs-open`): importing `mesoQLSkill` from the format into it failed that test;
  hence the generated data module.
- **Differences from prism.md §8**: `focus_meso` has `select` only (§4.5 says `framing?`, the operation has none);
  `get`'s `document` detail prints the whole S-expression, not at most the state lines (a document with many populations
  is long); `open`'s and `show_meso_view`'s messages still carry the title and the view's label unquoted (the
  operations' own words); tours (`mesoviewspec.tour.play`) have no tool.
- `meso-molstar` gets `@molstar/ai` as a dev dependency (the scripted model), and its lockfile entry.
- Windows: Biome's `--write` over a directory rewrote every file's line endings (the tree is CRLF, the index LF); the
  untouched ones were restored with `git checkout --`. Biome on the files changed, one by one, is clean.
