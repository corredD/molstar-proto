  coding, efficient and optimized. No repetition with existing code."
- **Check:** a volume loads from an OME-Zarr URL, e.g.
  `https://files.cryoetdataportal.cziscience.com/10003/TS_08/Reconstructions/VoxelSpacing6.802/Tomograms/100/TS_08.zarr`,
  at a chosen level (default the coarsest, level 2 = 232x232x113 at 27.2 Å, one 256³ chunk), and overlays the MRC of the
  same tomogram (same grid placement within one voxel). The membrane mask
  `.../Annotations/101/membrane-1.0_segmentationmask.zarr` (|i1) loads and shows as an isosurface at 0.5 with the
  existing isosurface representation.
- **Facts checked 2026-11-02 (curl):** Zarr v2, NGFF 0.4 `multiscales` (axes z,y,x, unit angstrom, per-level `scale` [+
  maybe `translation`]), chunks 256³, `dimension_separator` "/", order C, compressor
  `{id:'blosc', cname:'lz4', shuffle:1, clevel:5, blocksize:0}`, dtypes `<f4` (tomograms) and `|i1` (masks),
  fill_value 0. Files host sends `Access-Control-Allow-Origin: *` on plain GET (no custom headers: a Range header would
  preflight and get 403, so never send one). Missing chunks (404) = fill_value.
- **Build:**
  1. `packages/io/src/reader/zarr/`: `.zarray`/`.zattrs` parsing (typed, validated), NGFF multiscales; a store
     abstraction `get(key): Promise<Uint8Array | undefined>` (HTTP over the plugin's existing fetch/asset path; a File
     map for local), chunk assembly into one typed array of the level (z,y,x → Mol*'s grid axis order, check against the
     ccp4 path), dtypes `<f4 |i1 |u1 <u2 <i2 >f4`(endianness), `filters: null` only.

     typesize, blocksize, ctbytes), per-block split streams, LZ4 block decoder, byte-unshuffle. zlib via the existing
     `packages/core/src/util/zip/inflate.ts` (reuse, do not copy); zstd, bitshuffle: a clear "unsupported" error. Hot
     path: preallocated output, no per-byte allocation, `copyWithin` for overlapping matches where it is a win. Tests:
     vectors made by python `numcodecs` (conda env, below) for lz4+shuffle, lz4 noshuffle, memcpyed, zlib, several
     typesizes; and a decode-throughput micro-bench (MB/s) recorded in this file.
  3. A volume format in `plugin/core/src/state/formats/volume/` built the way ccp4 builds its `Volume`/`Grid` (reuse
     `volumeFrom*` helpers in `@molstar/model/formats/volume/*`; no new volume model): params level (default coarsest),

     transform from a URL string that reads keys lazily; look at how density-server / volseg fetch before writing a new
     path). Add a size guard: refuse above a param limit (default ~512 MB decoded) with a clear message.
  4. Lazy: the reader and decoder load only when a zarr opens (record
     `node scripts/esbuild/app.mjs apps/prism-viewer --prd` index.js size before and after).

## Decided

- **Pure TS blosc (brief), not the plan's WASM**; the 512 MB refusal (brief), not the plan's 200 MB warning. Cache API
  for chunks (plan B.3) not done: not in the brief.
- 404 is told by a typed core error (`DownloadStatusError`), not by parsing the message; only 404 = fill value (a 403
  stays an error, or a broken store reads as zeros).
- Chunks through `plugin.managers.asset.resolve(Asset.Url, 'binary', false)` (custom asset managers honored, nothing
  held).
- Two transforms (metadata node, volume node with the level param) plus a root action; not a `DataFormatProvider` (a
  Zarr is a directory, not bytes).
- `coarsest` = the level with the fewest bytes (not the list order).
- Stats over finite voxels, sigma = std (as the MRC's ARMS), not core `arrayStats`' rms (cube/dx's convention): the
  brief's overlay with the MRC holds for relative iso values too (gate finding 2).
- The size guard counts voxels + one decoded chunk (gate finding 4).
- Grid as CCP4's (spacegroup P 1, fractional box from translation): the overlay test compares the grid-to-Cartesian
  transform directly. `periodicity: 'none'` (CCP4 says `xyz` for a whole cell; a tomogram is not a crystal).
- Space axes: any order of x, y, z, the last three; leading axes must have 1 element (multi-channel refused).
- LZ4 lives in `reader/zarr/` (brief) rather than `core/util/zip`: worth moving if another reader needs it.

## Learned

- numcodecs 0.15 ignores the Blosc `blocksize` argument: multi-block vectors come from clevel 1 (64 KiB blocks) and
  size; the "don't split" flag (0x10) from tiny buffers or typesize > 16 (a `V32` view).
- The portal's level 2 has no NGFF translation: its voxel i sits at 4i·6.802 Å, while the binned voxel's centre is
  (4i+1.5)·6.802 Å: 0.375 of a level-2 voxel off the MRC, within one voxel, and what the metadata says.
- With `revertOnError`, `commit()` resolves (does not reject); the state logs the error. The action checks
  `selector.isOk` before the visual.
- Core `_inflate` returns the caller's whole buffer for an empty deflate stream (`03 00`) and core `inflate` never
  checks the Adler-32: callers that need exact output check both (`zlibDecode`).
- An S3 "directory" URL (`.../Tomograms/100/`) is 404: no listing; everything comes from `.zattrs`.
