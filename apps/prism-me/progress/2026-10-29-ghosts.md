## Design (measured before building, 2026-10-29)

**How it draws.** A clip object gets an optional `ghost` flag (`Clip.Params`, beside `tag`; a bitmask uniform
`uClipObjectGhost` per object). The renderer draws the representations with a ghosted object once more, in the depth
variant, into the transparent depth target, with a new render mask (`MaskGhost`). In that draw a ghosted object is
inverted (`clipInverted`, GLSL and WGSL): what it cuts is kept and what it keeps is cut; the other objects still cut.
The fragments are written with a fixed alpha below 1. The outline pass already finds the edges of that target (its
transparent outlines, alpha `clamp(a, 0, 0.5) * 2`), so the cut part shows as faint outlines only, one per object (depth
edges, as cellVIEW's ID-buffer edges). Color, pick, marking, shadows and SSAO never see the ghost draw: not pickable, no
fill.

- **Why this way.** The flip sits in the one function every clip path reads (instance, element `dClipPrimitive`, pixel
  and the impostors' `clipExit`, the clipping table's cut mode), so all of them get ghosts without code of their own.
  Rejected: (B) an app-side second representation with the inverted clip and a high transparency: no graphics lines, but
  it doubles the representation's memory and every pass, and its fill cannot be removed (the outline alpha is the
  fill's). (C) the marking pass's mask edges: one outline around the whole cut region, not per object; and a third
  marker type through the antialiased mask, more lines.
- **Gates it must pass** (each a line in the change): the draw table's `DrawFact.Ghost` (the pass's check: ghosted, not
  transparent), a scene aggregate `hasGhosts` (dirty-flagged as `hasAnimation`), the transparent depth drawn when
  outlines are on and the scene has ghosts (one helper for the three draw paths, which repeated it), the outline pass's
  transparent outlines and the composite's transparent blend on with ghosts (the transparent color cleared when nothing
  else is transparent).
- **Ghosts with the app's look.** Its outlines leave transparent objects out (`includeTransparent: false`): with ghosts
  the transparent depth then holds the ghosts only, so no transparent layer gets outlined.
- **Limits, recorded.** Several ghosted objects on one representation show what all of them cut (their intersection, the
  flip's), exact for one. Graded ways (keep, wider) invert as a whole. Ghosts need outlines on; the traced illumination
  path draws none (left open). Off (no ghosted object), nothing changes: no fact, no draw, same programs.
- **Cost.** One more depth draw of the ghosted representations only, when outlines are on; measured below on WebGPU.
- **Size, measured before building.** Core `clip.ts` ~10, schema and geometry values ~6, GLSL and WGSL clip and depth
  ~25, draw table and scene ~20, renderer pass ~15, draw and postprocessing gates ~30: ~110 graphics lines, under the
  150 of the brief. Prism's `clipping.update` `ghost` ~20, the app's toggle ~25.

## Decided

- The flip in `clipInverted` rather than ghost code per clip path (design note). Several ghosted cuts on one
  representation: their intersection, recorded in clipping.md §6.
- Ghosts are the outline pass's transparent outlines; with the app's look (`includeTransparent: false`) the transparent
  depth holds ghosts only. A color of their own (`transparentColor`) because black ghosts vanish on the dark theme (seen
  in the browser); null by default so nothing else changes.
- The control is a ParamsForm switch, as Invert's (the mock's pressed button would be a control of our own).
- Built the app control before clip-whole and graded-cuts-ui landed (neither merged at the time; #22 open): a testable
  slice for Ludo; merge origin/prism-me when they land, keep both.

## Learned

- A new pass needs its variant among `ShaderManager.getRequired`: WebGL2 threw "program not finalized: depth" after the
  first ghost; WebGPU was fine.
- `Button` passes no `data-*` attributes; tests find Prism switches by their label (`aria-labelledby`).
- Pre-existing on origin/prism-me, not this lane: clips-category.test.tsx "keeps a clip's compartments … (M2)" and
  "lists what it is given; Cut also and × …" (times out) fail on the base too (PR #21 fixes the merge).
