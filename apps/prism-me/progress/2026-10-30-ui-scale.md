# UI scale (2026-10-30, `me/ui-scale`)

Brief by the coordinator; the lane appends what was built, decided, learned, and the size against this.

## What Ludo wants

"Something really important": the whole UI larger, more readable, without touching the 3D viewer. Control (Ludo,
2026-10-30): a **UI scale** row in Settings › Appearance with − and + buttons.

How he checks it: open the app on 1344+, Settings › Appearance › UI scale, press + a few times: the panels, the tree,
the properties, menus, tooltips, the command menu and the bars grow; text stays crisp; the 3D picture (its resolution,
its labels) does not change, only the canvas region gets smaller as the panels grow. − goes back; a reload keeps it.

## Approach (coordinator, from the code; Ludo picked the control, not the mechanism)

Scale Prism's size tokens, not CSS `zoom` (zoom puts measured positions off: popovers, tooltips, drags, a virtual list's
scroll).

1. `theme.css`: the size tokens (`--msp-font-size-*`, `--msp-space-*`, `--msp-row-height`, `--msp-control-height`,
   `--msp-label-width`, `--msp-icon-*`, radii) become `calc(Npx * var(--msp-ui-scale, 1))`; 1px hairlines stay. The
   variable is set on Prism's shell root (not `documentElement`: an embedding page and Storybook stay as they are).
   `styles:check` (`ui/scripts/css.mjs`) still reads the scale.
2. JS sizes follow one `uiScale` state: the virtual lists' `rowHeight` (26 in the trees, 30 in the log; one rounded
   value used by both the list and the row's CSS, or long lists drift), icons given a numeric size, splitter and panel
   min/max widths.
3. The 11 literal `font-size`s move to tokens. Of the ~800 other px literals, fix in this lane only those that clip text
   at the largest step (dock panel widths, fixed card heights); the rest go to Prism's TODO.md.
4. The setting is a UI preference, stored as Prism stores the theme (per browser, localStorage in try/catch): never in
   canvas3d props or a state snapshot. Steps 100, 112.5, 125, 137.5, 150 % (near whole pixels on 2px and 14px tokens).
5. The row: shared `Button`s and icons (or ParamsForm if it has a stepper), the value shown between − and +. A command
   for each direction if it is an operation (`full-spec.test.ts`), with a shortcut only if Ludo asks.

## Spec

Prism's `ui/_spec/styling.md` (a UI scale section: what scales, what does not, the rounding rule for row heights) and
the settings spec where Appearance lives; `apps/prism-me/_spec/features.md` gains the row.

## Decided (the lane)

- **Tokens, not CSS `zoom`** (coordinator, from the code; Ludo chose the control: a − / + row in Settings › Appearance).
- **The lists needed no JS scale**: `VirtualList` and `RecycledList` already measure their rows (the `rowHeight` prop is
  the first guess), so a whole-pixel CSS row height is enough against drift; the brief's "JS row heights follow a state"
  fell away.
- **Box sizes in px scale too, not only the tokens**: with only the tokens the text grew in 26px rows and clipped. A
  mechanical sweep (heights, widths, line heights, font sizes, offsets, grid tracks); padding and margin were tokens
  already. Left: borders, shadows, transforms, negative `off-scale` hit-area offsets, and the sequence views (Seq\*
  measures and draws them: `views/sequence/` untouched).
- **The rail**: its step stays chosen by its height in px (as the container queries choose it), its buttons counted at
  the scale (`fitRail(entries, height, scale)`): a step by height ÷ scale would disagree with the CSS and overflow.
- **Steps** 90–200 % in whole percents (the advisor's near-whole-pixel steps traded for a plain value; the rounded
  tokens carry the pixel-exact parts). No shortcut: Ludo did not ask.

## Learned

- `pnpm format` on this Windows checkout (autocrlf, CRLF working tree) rewrites every file's line endings: ~5,600 files
  showed modified with no content change. Format the lane's files only (`biome format --write <files>`,
  `prettier --write <md>`); `pnpm format:check` fails here on line endings alone (5,430 files), not on content.
- Bash in this harness breaks on a non-ASCII character in a command (`§`, `✓`): use a script file.

## Open

- The default dock widths (the right panel's 340px and the others' sizes, user-resizable and kept) stay in px: at 150 %
  the panels feel narrow until widened. A follow-up: scale the defaults (not the kept sizes).
- `compactWidth` (720px) does not follow the scale: a larger UI could go compact sooner.
- Inline px in TSX (a few views set sizes in `style={{}}`) were not swept.
- The sequence band does not scale (Seq\*'s own sizes).

All four are in Prism's TODO.md now, with the container queries (review finding 7).
