## Decided

- `kind` in "set never changes a node's kind or id" is the node's field too (an entity's `kind`), not only its section;
  `set` refuses it and a node whose kind changes is replaced (skeptic's reading of Seq*'s rule; `diff` writes the
  replacement). No Opus design call was needed: §2 answered everything else.
- Inverses restore bytes: `set` that drops a field is undone by remove + insert in place; a list that empties comes back
  where the field order puts it; an edit after an id-less look is undone by a set of the view's whole `looks`.
- `emissive` is not carried to the MolViewSpec export: MVS primitives have no emissive (skeptic S7, refuted).

## Learned

- The review found that "undo byte for byte" has many corners (key order of a dropped-then-restored field, an emptied
  optional list, an id-less sibling as the anchor); a test on the examples with only multi-item lists missed them all.
- Final validation alone misses a duplicate id that exists only in the middle of a patch (insert a view with a look id,
  then remove the original): nested ids are checked as the node comes in.
- A transient `Errors 1` showed once in the heavy lane and not in two reruns.
- `typecheck:storybook` fails in `packages/prism/viewer/src/api/styles.ts` (a file this lane does not touch).
- Left open: S5 (diff of a mass reorder is quadratic: 4000 entities 250 ms; a typical edit is linear, nit).
